| 事实 | 值 | 对设计的影响 |
| --- | --- | --- |
| **join key** | 成交 `ask_order_id`/`bid_order_id` ↔ 委托 **`ex_order_id`**（~100% 可解析），**不是** `order_id` | 旧切片（000001，0.7%）用错 key，纯假象 |

## M2 — 单日 per-order 生命周期表（③-2, ③-3）

**目标**：产出"每笔委托怎么死的"表，是 ④ 的原料。

- [x] **M2-1 对齐管线**：join key = `orders.ex_order_id ↔ trades.{ask,bid}_order_id`；为每笔委托收集：被哪些成交消化、各消化多少、主动侧、时间区间。
  - 逐 stock-day 处理 + 内存分片（深市单日全量 ~1500 万委托行，避免一次性载入）。
- [x] **M2-2 一致性校验**：`Σ matched_vol ≤ submit_vol`；成交 sum 与委托匹配量对账；再与 `行情.cum_volume` 增量对账（设容差）。
  - 已完成：`20170123 / 000725.SZ` 订单-成交-撤单对账通过，负剩余 0；普通成交量、`行情.cum_volume`、行情逐 tick 正增量三者完全一致。
- [x] **M2-3 终态定义（诚实版）**：撤单在成交流中显式可见 → 终态定义为 `FULLY_FILLED / FULLY_CANCELED / PARTIAL_FILLED_CANCELED / PARTIAL_OPEN / UNFILLED_OPEN`；剩余量日终未完成。
- [x] **M2-4 生命周期特征**：驻留时间 τ（提交→最后成交/撤单；OPEN 只给下限）；冰山/拆分初检（同方向高频连续小单、量价重复模式）为 ④-1 备特征。
  - 已完成：基础驻留、成交/撤单/剩余、主动/被动成交量；冰山/拆分初检仍作为增强特征待补。

- 产出：per-order 表（parquet，放 `../../reports/l2_l3/` 或 `outputs/`，按体积定）。

**退出标准**：对账在容差内；抽样抽检全过；表结构固定可复跑。

## 已知坑（写代码前先记住）

1. **join 用 `ex_order_id`**，旧 processed 切片（`a_share_l2_hf_20170125_000001` 等）是坏数据，别当参照；600519 委托为空 = 沪市无委托流，正常。
2. **撤单在 `逐笔成交.trade_code='C'`**，不是 `逐笔委托.order_type`；终态对账必须把 fill 和 cancel 分开。
3. **bs_flag 深市空值主要来自撤单行**；对普通成交仍需做空值检查，M3-2 保留主动方向清洗。
4. **集合竞价 9:15–9:30** 匹配机制特殊，聚合时独立标记，别混进连续竞价。
5. **价格/体积单位未定刻度**，特征工程前先过 M1-1 校准。
6. **沪市无委托流** → ③④ 全部结论限定"深市"。
7. HMM 已改成项目内自包含实现；数据读 1500 万行级 → 按 stock-day 分片，别整表进内存。
